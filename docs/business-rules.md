# 排班系统 · 业务规则

> 这份文档是排班系统的「业务规则说明书」。以后设计数据库、写后端接口、写自动排班算法，都以这里为准。
> 规则有变化时先改这里，再改代码。
>
> 最后更新：2026-11-02（班表按月保存：只能新建下两个月、店长可按天修改、备注、提交）

参考场景：日本的烤肉店（一家店，两个部门，两个班次）。

---

## 1. 班次

| 班次 | 时间 | 厨房默认需要 | 服务员默认需要 |
|---|---|---|---|
| 白班 | 10:00 - 15:00 | 3 人 | 2 人 |
| 晚班 | 17:00 - 23:00 | 3 人（和白班相同） | 3 人 |

- 15:00 - 17:00 是店休时间，不算工时。
- **厨房白班和晚班的人数必须相同**：厨房全是上全天班的正社员，白天和晚上是同一批人，所以厨房只设一个数字「厨房每天需要几人」。
- 服务员的白班、晚班人数分别设置。
- 这些人数**店长可以在设置里修改**。

## 2. 部门

| 部门 | 由谁组成 |
|---|---|
| 厨房 | **必须全部是正社员**（没有兼职） |
| 服务员（大厅） | 正社员 + 兼职 |

## 3. 雇佣类型

### 正社员

- **默认每周上 4 天，每天都是全天班**（白班 + 晚班，10:00 - 23:00，中间店休 2 小时不算工时）。
- 厨房和服务员的正社员都按这个规则排。
- 正社员一天会同时占白班和晚班两个位置。

### 兼职（只有服务员有）

- 一天最多上一个班（白班或晚班）。
- 上班时间不固定（哪几天能来、一周能来几天都因人而异），**所以系统不自动排兼职，由店长手动填**。
- 用来填补正社员排完后剩下的空位。

## 4. 每天需要的正社员（新建排班时店长可以调）

| 部门 | 每天需要的正社员（默认） | 至少需要的正社员人数 |
|---|---|---|
| 厨房 | 3 人 | 向上取整(3 × 7 ÷ 4) = 6 人 |
| 服务员 | 2 人 | 向上取整(2 × 7 ÷ 4) = 4 人 |

- 店长在「新建排班」弹窗里用 + − 调整（例如厨房改成 4 人、5 人），调的**只是正社员**。
- 兼职上班时间不固定，不在这里调，排班后由店长手动填。
- 服务员每天至少要有 1 名正社员指挥大堂（默认每天 2 名，自然满足）。
- 厨房：全部是正社员，这条自然满足。

## 5. 登录角色（权限）

| 角色 | 谁 | 能做什么 |
|---|---|---|
| 店长 | 店长 | 管理员工、生成和修改排班、审批请假、修改设置（包括每个班次需要的人数） |
| 员工 | 厨房正社员、服务员（正社员 / 兼职） | 看自己的排班、看整月班表、申请请假 |

注意区分三个互相独立的属性：

- **部门**（厨房 / 服务员）：决定排进哪个部门的班
- **角色**（店长 / 员工）：决定登录后能做什么
- **雇佣类型**（正社员 / 兼职）：决定怎么排（全天 4 天 / 填空位）

## 6. 排班流程

**自动排班只排正社员**（规则固定、可预测的部分），兼职由店长手动填。

1. **自动排厨房正社员**：每天按需要的人数排，每人每周最多 4 天全天班。
2. **自动排服务员正社员**：默认 2 名，保证每天至少 1 名（例如一人上前四天、一人上后四天，中间重叠一天）。
3. **正社员天数尽量平均**：每次选人时，选「本月到目前为止上班天数最少」的人（上周少上的，这周会被优先补上，一个月下来大家差不多）。不是随机。
4. **服务员剩下的空位显示为「待填」**：店长根据每个兼职的情况（周末能不能来等），在月历上点开空位，手动选兼职填进去。系统只做基本检查：同一个人同一天不能排两次。
5. **厨房排不满就留空并标红**：说明厨房正社员人数不够，由店长自己处理。
6. **请假在班表出来之后提出**：批准后，把他那天的班改成休息；那天因此少人时，月历上显示缺人。
7. **长期休假中的员工不参与排班。**
8. 排好后店长可以手动增删。

## 6.5 班表的管理

- **新建排班只能选下个月和下下个月**（例如 11 月时只能新建 12 月、次年 1 月的班表）。已有班表的月份再生成会覆盖。
- **排班页能看三个月**：当前月、下个月、下下个月，用左右箭头切换。
- **只有店长能新建、修改、提交班表**；员工只能查看。
- 点月历上的某一天可以修改当天人员：正社员按白班、晚班分开显示，可以只移除某人的白班或晚班再换给别人（员工之间换班）；也可以给服务员添加兼职（选白班或晚班）。
- 每个月的班表可以写**备注**。
- 改过的班表变成「草稿」，店长点「提交班表」把整个月的数据一次性提交到后台。

### 班表的数据格式（一个月一个对象）

```ts
{
  id: "2026-12",                // 一个月只有一份班表，用年月当 id
  name: "2026年12月 班表",       // 系统自动生成
  year: 2026, month: 12,
  note: "24 号年末聚餐",          // 备注
  settings: { kitchenPerDay: 3, hallPerDay: 2 },   // 生成时用的人数设置
  status: "draft" | "submitted",
  updatedAt: "2026-11-02T08:00:00.000Z",
  days: [                       // 这个月每一天，长度 = 天数（28 ~ 31）
    {
      date: "2026-12-01",
      kitchen: { day: [1, 3, 5], evening: [1, 3, 5] },   // 厨房正社员：白班 / 晚班（默认同一批人 = 全天班）
      hall:    { day: [2, 8],    evening: [2, 8] },      // 服务员正社员：白班 / 晚班
      partTime: [{ employeeId: 6, shift: "day" }]   // 服务员兼职（店长手动填）
    }
  ]
}
```

## 7. 系统不管的事情

- **换班**：员工之间私下调换，系统不记录、不处理。
- 缺人时去哪里找人、要不要加班。

## 8. 人数估算（系统帮店长算，只提示不阻止）

店长修改需要的人数时，系统马上算出提示。人不够时**只提示，不阻止**保存和生成班表。

**单位「工作量」**：一个人上一天班 = 1 个工作量。

### 厨房（只有正社员，可以算得比较准）

- 厨房每天需要 N 个人 → 每天需要 N 个工作量
- 一周 7 天 → 一共需要 N × 7 个工作量
- 一个人一天最多提供 1 个工作量，一周最多上 4 天 → 一个人一周最多提供 4 个工作量
- 至少需要的正社员 = 一周需要的工作量 ÷ 4，除不尽就向上取整（人不能是小数）
- 例：每天 4 人 → 4 × 7 = 28 个工作量 → 28 ÷ 4 = **7 名**
- 例：每天 3 人 → 3 × 7 = 21 个工作量 → 21 ÷ 4 = 5.25 → **6 名**
- 提示示例：「厨房一周需要 28 个工作量，现有 6 名正社员最多提供 24 个，还差 4 个，约缺 1 名正社员」

### 服务员

- 正社员默认 2 名，保证每天至少 1 名指挥大堂。
- 兼职由店长手动填，所以不做事先估算；**生成班表后直接提示「本月服务员还有 X 个空位待填」**。
  - 例（默认白 2、晚 3）：一周 35 个班次，2 名正社员上全天班占 16 个，每周约 19 个空位待填，一个月约 80 个左右。

### 注意

这是按「每周总量」的估算。总数够也可能某一天缺人（例如周末兼职都来不了）。生成班表后，月历上标红的格子才是准确结果。

## 8.5 已确定不做 / 以后再做（2026-11-02）

- **手动修改不强制「每周最多 4 天」**：4 天是自动排班的默认规则；店长可以灵活调整（例如安排加班），编辑时只显示「本周已上几天」作为参考。
- **服务员兼职的空位不做提示**：兼职时间灵活，由店长自己安排。
- **员工端看完整班表**：不单独做「我的排班」，员工也想知道自己和谁一起上班。
- **请假功能以后再做**（申请、审批、批准后把那天改成休息）。
- **首页「今日排班」读排班页的同一份班表**；以后两边一起换成接口。
